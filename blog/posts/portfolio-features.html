Cloud Portfolio: Features and Reliability Controls

July 12, 2026 · 5 min read

The visible product is intentionally straightforward: visitors can review experience, browse projects and articles, and submit an opportunity through the contact page. Behind those pages, the platform includes delivery and operational features that make it behave more like a maintained service.

Visitor-facing features

  • Responsive homepage, experience timeline, project case studies, and long-form blog posts.
  • Accessible mobile navigation and persistent light/dark theme preference.
  • A contact form backed by a Node.js/Express API and Amazon SES SMTP.
  • Path-based URLs that keep every service under one public domain.

Delivery features

Each service has its own GitHub Actions workflow. A release passes code and image validation, uses separate build and production approval gates, publishes a Docker image tagged with the Git commit SHA, and updates only the selected Compose service. A master workflow exists for coordinated platform releases.

Reliability and recovery

  • Container health checks and post-deployment HTTP validation.
  • Smoke tests for core pages, blog subpages, and the contact API contract.
  • Persisted release history that retains the previous verified image for N-1 rollback.
  • A manual rollback workflow with an explicit image tag or previous-release selection.
  • Sequential full-platform deployment to limit simultaneous change.

Operational reporting

A scheduled job generates an HTML report containing service health, infrastructure and security information, deployment and rollback readiness, route performance, and approximate page-view data. Amazon SES SMTP delivers the report. This turns operational state into a repeatable artifact instead of relying on manual checks.

What I would add next

The next useful improvements are structured application metrics, centralized logs with retention, automated restore testing, and a documented SLO for public routes. Those additions would improve evidence of reliability without changing the visitor experience.
